# 网页剪藏加固对照 / Web clipping hardening review

本记录将 WeChat Diary 公开 PR 审查中出现的故障类型，与 Omnichannel Diary 的独立实现逐项对照。它只用于行为验收和回归设计；没有从其他项目复制源文件、测试、fixture 或样式。

| 检查项 | 对照结论 | Omnichannel Diary 处理 |
| --- | --- | --- |
| 默认只剪藏公众号 | 不适用 | 本项目的产品范围就是全渠道网页、文档、PDF 和技术社区；保留“自动剪藏网页”总开关，不退回微信专用行为。 |
| 公众号正文根节点 | 已有主要防护，仍缺页面噪音清理 | 继续优先 `#js_content`，并清理二维码、工具栏、底栏、广告和弹窗节点。 |
| 代码块缩进和空行 | 部分存在 | fenced code 改为独立状态清理，不再压缩代码内部缩进或空行。 |
| 嵌套列表层级 | 存在 | 按 DOM 列表深度生成缩进，保留有序列表起始编号。 |
| 网页 Markdown / Obsidian 语法注入 | 存在 | 文本节点统一转义 Markdown 控制字符、Wiki 链接/Embed、`%%`、HTML 和危险围栏；插件自己生成的链接与图片语法不受影响。 |
| 标题换行或结构字符破坏笔记 | 部分存在 | 标题压成单行、移除控制字符，并在 Markdown 标题中转义。 |
| 自定义 UA 导致公众号跳转 | 存在 | 网页请求改用不带插件名称/版本后缀的标准浏览器 UA。 |
| 公众号长链参数波动和长短链重复 | 存在 | URL 参数优先，页面变量需通过格式校验；`biz + mid + idx` 统一为稳定身份，短链仅作兜底，跟踪参数不参与文件身份。 |
| 公众号发布时间 | 缺失 | 读取页面 `createTime` / `publish_time` 等可信时间字段并写入 frontmatter。 |
| 图片串行下载阻塞消息 | 存在 | 单篇最多 4 张并发；同一条消息中的多个网页最多 2 篇并行，并共享总处理截止时间。 |
| 单图和整篇时间预算 | 存在 | 单图最多 10 秒、仅连接重置重试一次；单条消息默认 75 秒，15–180 秒可配置。 |
| 图片数量和总容量 | 存在 | 默认每篇 30 张、总计 50 MB，均可配置；超限或超时保留远程图片地址并写明失败数量。 |
| `requestUrl` 优先再回退 Node | 不适用 | 本项目使用带 DNS/重定向 SSRF 校验的独立流式网络层，不能用自动跟随重定向且不暴露最终地址的调用替换安全边界。 |
| 原句块的空行和结构前缀 | 存在 | CRLF 统一、连续空行收敛，并保护行首标题、分隔线和保留标记。 |
| 一条消息多个链接 | 已在同一每日笔记段落，仍会串行放大等待 | 保持一个消息块和全部入口，同时让所有链接共享同一个处理预算。 |
| 重复链接回执 | 缺失 | 根据稳定身份复用原剪藏路径，中英文回执明确说明“之前已经保存，已复用”。 |
| 撤回剪藏入口 | 不适用 | 当前版本没有宣称或实现聊天端“撤回”命令；帮助文案要求用户直接在 Obsidian 中修改。 |
| 上游版本号、文案和迁移块回退 | 不适用 | 这些属于另一仓库的 PR 合并边界，不是本项目缺陷；本项目的设置迁移保持独立，0.4.7 发布版本已在 Manifest、Package 与版本映射中同步。 |

对应回归测试位于 `tests/webclip.test.js`、`tests/network.test.js`、`tests/reliability.test.js`、`tests/router.test.js` 和 `tests/settings.test.js`。
